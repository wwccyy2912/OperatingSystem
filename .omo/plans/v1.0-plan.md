### 1.2 已知差距（5 路 explore 实测结论）

| 领域 | 差距 | 关键事实 |
|---|---|---|
| **包管理器/.ops** | ❌ 无 `pkg_manager` 服务、无 `.ops` 格式、无沙盒应用容器 | 16 服务里无 pkg；`SYS_PROCESS_CREATE` 无 cap 门控（未按 manifest 授权）；requirements.md §5.2 沙盒流程未实装 |
| **窗口管理器** | ❌ 无 WM 服务、无 surface/合成、libtui 仅 primitive ops（write/clear/status/box/render_line/cursor/printf） | tui_demo（76 行完整 demo）可编译但**未接入 Makefile**；term 独享 framebuffer；keyboard 单焦点 `s_focus_owner` + parked[4] |
| **鼠标** | ❌ 无 PS/2 aux 驱动 | IRQ 表 16 线（PIC 0-15，IRQ0/2 保留）；keyboard.c 是现成模板 |
| **音频** | ❌ 无音频服务/驱动 | 被 D7（MMIO 映射）卡住；需 `SYS_MAP_MEMORY` 设备 MMIO 支持 + `CAP_AUDIO_HW` |
| **网络** | ❌ 无网卡驱动/协议栈 | virtio-net legacy 可仿 virtio_blk.c（DMA 环 + 轮询）；QEMU `-device virtio-net` 可用 |
| **多媒体/开发者模式** | ❌ 无屏幕捕获/编解码/dev 模式 | SYS_FB_MAP 已存在（地基可用）；完全空白 |
| **Signal 用户态化** | ⏸ 内核 signal.c 暂留，原语已备（SYS_THREAD_SET_CTX） | roadmap P2 遗留项；hello.elf 实测信号自测通过（内核态） |
| **SMP/性能** | ❌ 单核；Futex/多活动调用/零拷贝推迟到 SMP 阶段 | roadmap P3；`s_active_call` 单活动调用/端口 |
| **文档** | ❌ requirements.md §9 要求 kernel.md / ipc_protocols.md / security_model.md + 用户手册 | docs/ 现有 7 份，缺这 4 份 |

### 1.3 硬约束（不可违反）

- 禁改 `user/services/vfs/fs_mem_driver.c`（用户明令）。
- 不 `git add/commit` 除非用户明确要求。
- 新 syscall 必须 `cap_lookup(RIGHT_*)` 门控；编号追加不重排；`SYS_COUNT` 同步
  （`kernel/include/kernel/syscall.h`）。
- 头文件契约冻结后并行任务间不可互改契约（先定契约、再并行实现）。
- IPC 消息上限 4096B（`MAX_MSG_SIZE`）；类型 `_t`；错误码负数；行宽 ≤100；
  4 空格缩进；全局 `g_`/静态 `s_`；`模块_动词_名词`。
- TUI 面板显示「应用名 (PID n)」，禁止 hash；边框仅 ASCII `+ - |`。

## 二、阶段划分（依赖序，每阶段独立验证）

### Phase A —— v0.3 补完：包管理器 + .ops + 沙盒应用容器

**目标**：`pkg install/run` 能安装并运行一个带 manifest 声明的沙盒应用（hello.ops）。

**A1 契约冻结（先行）**：
- `.ops` 格式定义（`docs/ops_format.md` 或并入 runtime_design.md）：魔数 +
  版本 + manifest（JSON 或键值文本：app_name/app_id/entry/permissions[]）+
  payload（ELF blob）。先做**单 ELF + 文本 manifest**（不做 squashfs，压缩后置）。
- 沙盒授权契约：`SYS_PROCESS_CREATE` 改造为按 manifest 授予初始能力
  （cap_create_atom 空表 + 按 permissions 逐项 grant_to_subject）。
  若评估后认为内核改动过大，**降级方案**：pkg_manager 用现有
  `SYS_PROCESS_CREATE` 拉起 + 立即 `cap_grant_to_subject` 授予 manifest 能力。
- 新服务注册 4 处：Makefile `USER_C`/`USER_SVC_ENTRY_OBJ`/`SVC_NAMES`/`SVC_LINK_RULE`。

**A2 实现**：
1. `scripts/ops_pack.py`（宿主侧打包工具）：manifest + ELF → .ops 单文件。
2. `user/services/pkg/pkg_manager.c`（新服务）：`pkg install <path.ops>`（解析
   manifest → 写入 `/Volumes/Users/Apps/<app_id>/`）、`pkg list`、`pkg run <app_id>`
   （读 manifest → 按权限列表授权 → spawn）。
3. libpkg 客户端库（`user/lib/libpkg/`）。
4. shell 命令 `pkg install/list/run`。
5. demo：把 hello（或新 app_demo）打成 hello.ops 预置到 System 卷 / Users 卷，
   `pkg run hello.ops` 全链路。
6. `docs/ops_format.md`。

**A3 验证**（QEMU + 串口/sendkey）：
- `pkg list` 列出已装应用；`pkg run` 后应用 PID 输出、exit 正常。
- manifest 声明 `serial` 权限的应用能写串口；未声明的被拒（沙盒生效）。
- make iso 0 警告；回归 31/31 不受影响。

### Phase B —— v0.4 补完：窗口管理器 + libtui widget + 鼠标

**目标**：`term` 之上有 WM 服务，tui_demo 作为窗口化应用运行，键盘焦点
在窗口间切换，鼠标（可选）驱动基础。

**B1 契约冻结（先行）**：
- WM 协议（`wm` 端口）：`WM_OP_CREATE_WINDOW`（title/w/h/x/y）→ window_id、
  `WM_OP_RENDER`（窗口内像素行）、`WM_OP_FOCUS`、`WM_OP_CLOSE`、
  `WM_OP_GET_FOCUS`。合成归属：**term 独占 framebuffer，WM 经 IPC 把窗口
  内容交给 term 绘制**（不做多进程共享 surface——避免 SYS_MAP_MEMORY 共享
  内存改动，符合 D5 轮询折衷与最小改动原则）。
- libtui 升级：新增 widget 层（`tui_window_t`/`tui_button_t`/`tui_label_t`/
  `tui_panel_t`），底层仍是 primitive ops，WM 协议客户端封装在 libtui。
- keyboard 焦点路由扩展：`KBD_OP_TAKE_FOCUS` 语义从「单所有者」升级为
  「WM 为焦点仲裁者」——保持现有单焦点机制，WM 申请焦点后再转发。

**B2 实现**：
1. `user/services/wm/wm.c`（新服务）：窗口表 + Z 序 + 焦点仲裁 + 与 term 渲染
   对接（把窗口内容经 `wm` 端口协议送 term 绘制；term 加 `term_draw_window`
   请求处理）。
2. libtui widget 层 + 事件循环（键事件经 keyboard parked 槽 → WM → 焦点窗口）。
3. tui_demo 改造为 WM 客户端，接入 Makefile（4 处）。
4. `user/services/mouse/mouse.c`（新服务，可选/后置）：PS/2 aux 驱动
   （IRQ12 + io_read8/io_write8 + 0x60/0x64 端口），事件经 `mouse` 端口广播；
   WM 把鼠标坐标用于窗口移动（若时间不足：鼠标后置，不阻塞 WM 验收）。

**B3 验证**：
- WM 启动后 tui_demo 窗口渲染（screendump OCR 见窗口边框 + 标题）。
- 焦点切换：窗口 A/B 各有一个按钮，方向键/Tab 在窗口间移动焦点，按键落到
  焦点窗口（串口日志证明）。
- make iso 0 警告；回归 31/31 不受影响；原有 TUI 权限面板仍工作（回归）。

### Phase C —— v0.5：音频 + 网络

**目标**：QEMU 下网卡可收发（virtio-net legacy）+ 音频服务可初始化（至少
静音 DMA 环可跑通或 PCI 枚举可见）。

**C1 网络（优先，仿 virtio_blk 已有路径）**：
1. 内核：`SYS_NET_*` 或复用 `SYS_BLK_*` 模式加 virtio-net 驱动
   （`kernel/arch/x86_64/virtio_net.c`）：PCI 枚举 + virtio-net legacy
   （Rx/Tx virtqueue，轮询或 IRQ 通知）+ 收发原语，cap 门控 `CAP_TYPE_PCI_DEV`。
   需要新增 syscall（追加编号）：`SYS_NET_INFO/SYS_NET_SEND/SYS_NET_RECV`。
2. 用户态：`fs_...` 模式改 `net_service`（`user/services/net/`）：绑定到网卡，
   暴露 `net` 端口；shell `net_ping`/`net_info` 自测（环回或 QEMU user 网络）。
3. **lwIP 移植列为后置**（协议栈体量大，v0.5 先做链路层收发验证 + 简单
   ARP/ICMP 回复，TCP/IP 栈作为 v1.0 文档期增强；若时间允许再移植）。
   —— 决策点：v0.5 网络「链路层验证」即算完成，不强制全协议栈。

**C2 音频**：
1. 内核：D7 落地——`SYS_MAP_MEMORY` 支持设备 MMIO（现有实现已按 cap 门控，
   扩 `CAP_TYPE_PCI_DEV` 的 MMIO 映射路径）；新增 `CAP_AUDIO_HW` 类型（可选：
   直接复用 `CAP_TYPE_PCI_DEV` + obj_id 指定音频设备，最小改动）。
2. 用户态：`user/services/audio/audio.c`（新服务）：PCI 枚举找音频设备
   （QEMU 默认无音频设备 → 用 `-device AC97` 或 `-audiodev`；先探测枚举可见），
   初始化 DMA 环，暴露 `audio` 端口（play/stop/volume 占位）。验收放宽为
   「PCI 枚举到音频设备 + 初始化不崩溃 + 端口可应答」，不要求真实出声。

**C3 验证**：`net_info` 显示网卡 MAC/队列；`net_ping` 回 ICMP（或至少链路层
自环回）；`audio info` 返回设备存在；回归不受影响。

### Phase D —— v0.6：多媒体 + 开发者模式

**D1 屏幕捕获服务**（复用 SYS_FB_MAP + SYS_PROCESS_CREATE）：
- `user/services/screencap/screencap.c`（新服务）：`screencap grab <w> <h>`
  经 term 端口取当前帧缓冲内容 → 写 `/Volumes/Users/Captures/<ts>.bin`；
  cap 门控 `CAP_TYPE_FRAMEBUFFER`（若内核有该 cap 类型；否则走 vfs 写授权）。

**D2 开发者模式**：
- `devmode` 开关（shell 内建或 kernel cmdline）：开启后暴露
  `dev_*` 命令（读内核日志缓冲、进程列表、cap 表 dump——均走现有
  SYS_PROCESS_LIST/SYS_DEBUG_LOG/SYS_PROC_INFO_BY_SUBJECT，不加新特权）。

**D3 验证**：`screencap grab` 产物字节数 = 帧缓冲尺寸；`dev ps` 列出全部进程；
回归不受影响。

### Phase E —— v1.0 稳定版：SMP / 性能 / 文档 / Signal 用户态化

**E1 Signal 用户态化**（roadmap P2 遗留，原语已备）：
- 内核 `signal.c` 语义收敛为「仅投递原语」（SYS_SIGNAL/KILL 保留最小实现或
  迁移）；`user/lib/libos/signal.c` 实现用户态处理（handler 表 + trampoline
  经 SYS_THREAD_SET_CTX 写入上下文 + sigrestore.S 已存在）。
- 验收：hello.elf 信号自测在用户态信号库下仍 PASSED（行为不变）。

**E2 SMP 多核**（最大工程，独立里程碑）：
- 启动：AP 唤醒（INIT-SIPI-SIPI）、per-CPU GDT/TSS/栈、`s_ticks` 每核独立。
- 调度：`sched_tick` 按核；`thread_set_affinity` 生效；spinlock 原子性复核
  （当前 CAS 在单核可关中断，SMP 需真 spinlock + memory barrier）。
- IPC：`s_active_call` → 多活动调用池（roadmap P3 项，SMP 前提）。
- 锁：Futex 化 Mutex（roadmap P3）。
- 验证：QEMU `-smp 2` 启动 + 1000 线程散布双核 + 100k IPC 不崩 + 回归全绿。

**E3 性能优化（P3 收尾）**：零拷贝读路径（CAP_TYPE_MEM 映射文件页）。

**E4 文档补齐**（requirements.md §9）：`docs/kernel.md`、`docs/ipc_protocols.md`
（各服务端口/消息结构全录）、`docs/security_model.md`、`docs/user_manual.md`
（构建/安装/包管理使用）。可用现有 vfs_design/tui_design/permission_model 拆分归档。

**E5 验收**：`make iso` 0 警告 + QEMU 全量回归（31/31 + P1 + P2V + 各阶段新增
测试）；`-smp 2` 启动验证；文档 4 份齐备。

## 三、并行化策略与契约纪律

1. **每阶段第一步：冻结头文件契约**（新服务 IPC 结构体、新 syscall 编号、
   libtui 公共 API、WM 协议）。契约文档先落 `docs/`，再并行实现。
2. **阶段内可并行**：
   - Phase A：pkg_manager（含 4 处 Makefile 接线）+ ops_pack.py + libpkg 可并行；
     manifest 授权改造与 shell 命令串行（依赖前者）。
   - Phase B：WM 服务 + libtui widget 层 + term 渲染扩展可并行（契约冻结后）；
     mouse 独立并行（不阻塞 WM 验收）。
   - Phase C：virtio-net 内核驱动 + net 服务可并行；音频独立并行。
   - Phase D：screencap + devmode 可并行。
   - Phase E：E1（signal 用户态化）与 E2（SMP）可并行（不同子系统）；
     E4 文档与 E2 并行；E2 内启动/调度/IPC/锁串行。
3. **每阶段验收门槛**：make iso 0 警告 → QEMU 阶段验证 → 回归全绿 → 进入下阶段。
4. **失败恢复**：单文件编译先验证（`make build/user/services/<svc>/<file>.c.o`）；
   2+ 次失败后 revert 到上一已知良好状态再继续。

## 五、风险与降级预案

| 风险 | 预案 |
|---|---|
| Phase E SMP 体量过大 | 拆子里程碑（E2a 启动/调度 → E2b IPC/锁），逐子步验收；文档 E4 先行不阻塞 |
| 音频无 QEMU 设备 | 验收放宽为 PCI 枚举可见 + 端口应答；AC97 失败则用虚拟设备桩 |
| lwIP 移植超期 | 链路层验证即算 v0.5 网络完成；TCP/IP 入 v1.0 文档期 |
| WM 共享 surface 复杂 | 合成走 term 单点（IPC 传窗口内容），不做多进程 framebuffer 共享 |
| .ops 沙盒授权需内核改 SYS_PROCESS_CREATE | 降级：spawn 后由 pkg_manager 立即 grant_to_subject（零内核改动） |
